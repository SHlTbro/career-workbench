# Career V-0 Web plugin (isolated integration)

This plugin adds a full-width Career page through DSH's native `main` Slot and a `sidebar.panellist` entry. The Host owns all Career JSON state, XLSX artifacts, temporary uploads, and Owner action credentials. The browser sends only action parameters through same-origin authenticated Connection Fetch routes. The Python bridge is spawned as `python -m career_v0.bridge` with JSON stdin; no shell command is built from browser data. Host forces UTF-8 Python stdio on Windows.

## Current user path

1. Open **Career 工作台** in the DSH Web sidebar. G0 shows the master-derived top-level project candidates and nested items. Owner fills target roles, scope, salary, every project inclusion/purpose/stack/status, nested decisions, and the three protected identity signal quotes and expressions. Choices start blank. **保存草稿** and **本人确认 G0** are separate actions. Confirmation is disabled when the form differs from the saved draft.
2. After G0, M1 can run DSH Search. Search results are labelled source leads with zero qualified jobs. The page then allows explicit Fetch of a lead, normalization of a readable capture, and explicit selection of normalized records for a candidate batch. Backend classification determines qualified/unknown/excluded counts. No lead is counted as a qualified job merely because Search returned it.
3. For a real batch, Owner downloads candidate XLSX, edits it outside DSH, selects the corresponding export version, uploads the workbook, reviews the parsed selection, and separately confirms G1. For a shortfall, an initially unchecked checkbox must acknowledge the actual qualified count and target. An empty selection cannot be confirmed. Batch, export and preview history can be recovered after a refresh.
4. After G1, M2 lists only selected jobs. A selected job with a retained full JD capture can create a source-grounded research record. For that selected company, the page can search public sources, let the user choose a link to Fetch, and extract exact business quotes from its capture. A company dossier is shared within the Campaign by exact company identity; each job keeps its own JD and plan. Source authority and application channels remain visibly unverified until independently checked. The DSH planning call then proposes one parameterized plan per job. The page shows strategy, every project's HERO/COMPACT assignment, protected signals, layout, risks, and exact plan/input hashes. Owner downloads the plan XLSX, edits it in Excel/WPS, uploads it for an independent preview, and explicitly confirms valid decisions at G2. No PDF is generated by G2 itself.
5. M3 can generate a candidate PDF only for the current G2 approval. Host checks that approval again after rendering. Mechanical QA requires two A4 pages, every included project, source order and protected text. A failed render returns to plan revision; it never silently removes content. Owner reviews the PDF and explicitly records G3 with its PDF hash and visual checks. Only a current G3 approval enables a downloadable handoff ZIP. Nothing submits an application.

## Route contract

All paths are under `/api/career-v0`, registered by `ctx.connection.fetch.register`; DSH rejects unauthenticated requests before Host handlers. JSON requests use `application/json`. The XLSX upload uses the Office MIME type as raw request body and is capped at 10 MB.

| Method | Path | Bridge operation / result |
|---|---|---|
| GET | `/state` | `inventory_candidate`, `list_campaigns` |
| GET | `/master` | authenticated read-only master text for exact Owner quote review |
| POST | `/campaign/draft`, `/campaign/revise`, `/campaign/confirm` | G0 draft/revision/Owner confirmation |
| POST | `/search-sources` | `search_sources`; returns leads only |
| GET | `/discoveries?campaign_id=` | `list_discoveries`; summarized lead/capture metadata |
| POST | `/source/fetch`, `/source/normalize` | `fetch_source`, `normalize_source` |
| GET | `/normalized?discovery_id=` | `list_normalized_sources`; summarized classification |
| POST | `/batch/create` | `create_batch_from_normalizations`; explicit normalized IDs |
| GET | `/batches?campaign_id=`, `/batch?batch_id=` | batch list/detail |
| GET | `/candidate-exports?batch_id=`, `/selection-previews?batch_id=`, `/selection?batch_id=` | reload recovery |
| GET | `/candidates/workbook?batch_id=` | `export_candidates`; XLSX bytes and `x-career-export-id` |
| POST | `/candidates/preview?export_id=` | Host-owned `_uploads` temp file, `preview_selection`; no G1 |
| POST | `/candidates/confirm` | `confirm_selection` with `preview_id` and explicit `accept_shortfall` boolean |
| GET | `/selected-jobs?batch_id=`, `/research?batch_id=`, `/plans?batch_id=` | selected-only M2 read views |
| GET | `/company-sources?batch_id=`, `/company-dossiers?batch_id=` | selected-company public-source history and reusable dossier |
| POST | `/company/search`, `/company/prepare` | selected-company Search and exact-quote extraction after a chosen source Fetch |
| POST | `/research/prepare`, `/plans/prepare` | source-grounded research and DSH plan draft, both after G1 |
| GET | `/plan-exports?batch_id=`, `/plan-previews?batch_id=`, `/plan-decisions?batch_id=` | G2 reload recovery |
| GET | `/plans/workbook?batch_id=` | real plan XLSX bytes and `x-career-export-id` |
| POST | `/plans/preview?export_id=` | Host-owned XLSX import preview; no G2 |
| POST | `/plans/confirm` | explicit Owner decision confirmation against plan/input versions |
| GET | `/resume-artifacts?batch_id=` | current candidate PDF and G3 status list |
| POST | `/resumes/generate` | G2-gated render and mechanical QA |
| GET | `/resumes/pdf?artifact_id=` | authenticated candidate PDF preview/download |
| GET | `/resumes/page-image?artifact_id=&page=` | authenticated SHA-checked rendered PNG page |
| POST | `/resumes/review` | explicit Owner G3 decision bound to PDF SHA256 |
| POST | `/handoff/export` | current G3-gated package creation; no application submission |
| GET | `/handoffs?artifact_id=`, `/handoff/zip?handoff_id=` | package history and authenticated ZIP download |

Host creates the Owner proof secret once per process. The browser never supplies `actor_channel` or the secret. The backend independently checks G0/G1 versions and workbook identity. A failed required call is shown as an error; there is no silent fallback.

## Real local launch

The checked-in startup script verifies the locked runtime and enabled plugin, then starts DSH Web with the actual read-only Master and a separate persistent Career state directory. It never fills a preference or performs an Owner gate. Use a fresh state directory for new live work. Do **not** use synthetic fixture masters for real Career work.

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File career_v0/start-workbench.ps1
```

The plugin is linked into your DSH web profile (add a `link:` dependency on this repo's `career_v0/web_plugin` and put `career-v0-web-plugin` into `dsh.profile.bundles`). Search and Fetch for Career run through the separate DSH headless bridge. `office-to-pdf` may report an import warning on Web boot; Career renders through Playwright Chromium and checks the result independently. The official CLI prints a local Web URL and one-time token on boot. Do not copy synthetic fixture state into live state.

## Evidence and limits

- Web mount spike (2026-09-27/28): real Web mount with authenticated Host state, draft save, anonymous API 401; a first-run Windows subprocess encoding issue was fixed with forced UTF-8. Synthetic `SIMULATED_OWNER` fixture runs also verified real Host XLSX export, unchanged-file upload preview, G1-disabled blocking on M2, and recovery of batch/export/preview state after browser reload.
- `../tests/test_company.py`: synthetic selected-only company source isolation, exact captured quote checks and same-company reuse without JD mixing. No real company source has yet passed through the Web page.
- `../tests/test_research.py`: a synthetic two-page PDF with mocked content QA proves the G3 state and ZIP package contract. It is not evidence of actual resume visual/content QA.
- On 2026-09-27 the Web profile booted on port 18380 against the then-current read-only Master; the authenticated Career page showed all seven top-level projects with blank Owner choices, M1/M2/M3 displayed their missing-gate blockers, and the Host returned zero real Campaigns with anonymous requests rejected (401). At that spike stage no real Owner gate had been performed; the first full real G0→G3 journey (search, fetch, normalize, plan, 2-page PDF, handoff) subsequently passed on 2026-09-29, recorded in the repository root README's verification section.
- DSH Search/Fetch/normalize UI and its Host routes are wired to bridge operations. The 2026-09-29 golden journey exercised the real search and fetch path end to end; live recruitment sites beyond that journey remain untested. The tool never performs the final application action: submission stays with the Owner.
